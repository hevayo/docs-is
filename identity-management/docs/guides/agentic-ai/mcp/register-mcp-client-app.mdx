The Model Context Protocol (MCP) specification defines that authorization is initiated by MCP clients. These clients handle authorization flows, manage tokens and sessions with MCP servers, and provide end-user experiences based on user permissions.

<Edition selfHostedFrom="next">

{edition.productName} provides an **MCP Client Application** template with default configurations to register an MCP client with minimal effort. This template has been configured to create an OAuth application that adheres to the guidelines and best practices outlined in the [MCP authorization specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization).

:::info[Other Application Types]
While the MCP Client Application template is optimized for MCP connections, MCP servers can also be accessed by most other application types in {edition.productName}, including Single Page Applications, Traditional Web Applications, Mobile Applications, and M2M Applications. The only exception is Digital Wallet applications, which cannot access MCP servers.
:::

</Edition>

## Register an MCP Client Application

To regiser an MCP Client application,  

1. On {edition.productName} Console, go to **Applications** > **New Application** to navigate to the application template selection wizard.

    <img src={require("../../../../assets/img/guides/applications/select-mcp-client-app-template.png").default} alt="Select MCP client application template" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

<Edition selfHostedFrom="next">

2. Select **MCP Client Application**.

    If [Client ID Metadata Documents (CIMD)](#enable-client-id-metadata-documents) are enabled for the organization, the wizard asks **Which MCP client are you connecting?** MCP clients such as Claude and Visual Studio Code identify themselves with a CIMD, an HTTPS URL that serves the client's name, redirect URIs, and sign-in details.

    <img src={require("../../../../assets/img/guides/applications/mcp-client-cimd-select-client.png").default} alt="Select the MCP client to connect" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

    Choose how to register the client:

    - **Known clients**: Select the client, for example **Claude**. {edition.productName} creates the application from the client's metadata document.
    - **Another client with a Client ID Metadata Document**: Select **Continue**, enter the **Metadata document URL**, and select **Fetch document**. Review the client details, edit **Application name** if needed, and select **Create**.

        <img src={require("../../../../assets/img/guides/applications/mcp-client-cimd-enter-url.png").default} alt="Enter the client's metadata document URL" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

    - **I'll configure it myself**: Select **Continue** and fill in the application creation wizard as described below.

    <img src={require("../../../../assets/img/guides/applications/create-mcp-client-application.png").default} alt="Create an MCP client application" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

    The MCP application creation wizard includes the following fields.

    | Parameter | Description |
    | --- | --- |
    | Name | A unique name to identify your application. |
    | Authorized redirect URL | The URL to which the authorization code is sent upon user authentication and where the user is redirected upon logout. |
    | Public client | Keep this enabled if your MCP client application cannot securely store client secrets. (Eg: mobile apps, single page web apps etc). |

    :::note
    MCP Authorization specification recommends that MCP clients should be public clients with authorization code grant flow enabled. However, if your MCP client runs on a server side environment where you can keep a secret, you can untick the *public client* option.
    :::

</Edition>

3. Click **Create** to complete the registration.

## Enable Client ID Metadata Documents

</Edition>

<Edition only="cloud">

Enable CIMD for the organization with the following API:

```bash
curl --location --request PATCH 'https://api.asgardeo.io/t/<organization_name>/api/server/v1/configs/authentication/inbound/oauth2' \
--header 'Authorization: Bearer <access_token>' \
--header 'Content-Type: application/json' \
--data '{ "enableClientIdMetadataDocument": true }'
```

</Edition>

<Edition only="self-hosted" selfHostedFrom="next">

Enable CIMD for the organization with the [Server Configuration API](../../../apis/configs-rest-api/index.mdx#op-updateOAuth2InboundAuthConfig):

```bash
curl --location --request PATCH 'https://localhost:9443/api/server/v1/configs/authentication/inbound/oauth2' \
--header 'Authorization: Bearer <access_token>' \
--header 'Content-Type: application/json' \
--data '{ "enableClientIdMetadataDocument": true }'
```

</Edition>
